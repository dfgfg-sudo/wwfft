## 一、AI Agent 的“操作系统”——Harness 技术

### 核心观点
未来 AI 开发的核心竞争力，将从调优大模型（CPU）转向掌握 **Harness** 技术。Harness 是 AI Agent 的“操作系统”，负责管理内存、调度工具、处理错误，是将 AI 从“玩具”变为工业级应用的关键桥梁。

**一个真正能落地的 Agent = Model (马) + Harness (马具)**

### 大模型的先天缺陷与致命失败模式
大模型本质上是**无状态（stateless）**的，像一个失忆症患者。在处理复杂长任务时，若不加以控制，会陷入以下失败模式：

| 失败模式 | 通俗解释 | 后果 |
|---------|---------|------|
| 上下文腐烂 (Context Rot) | 任务途中被干扰，忘记最初指令 | 任务目标丢失，工作跑偏 |
| 工具调用幻觉 | 无法精确提取参数，调用失败 | 陷入无限重试，任务瘫痪 |
| 失败时状态丢失 | 因网络波动等意外，进度清零 | 从头再来，无法容忍 |
| 过早停止 | 未验证结果就提前结束 | 交付不完整或错误的结果 |

### Harness 的操作系统类比
| 类比对象 | 在 AI 系统中的角色 |
|---------|----------------|
| CPU | 大模型 (提供算力和推理) |
| 内存 (RAM) | 上下文窗口 (临时存储数据) |
| **操作系统** | **Harness (管理资源、调度工具)** |
| 应用程序 | Agent (执行具体业务逻辑) |

### 顶级框架的 Harness 实践

**LangChain 极简定义**：
“如果你不是模型，那你就是 Harness”。除了模型本身，所有记忆管理、规划、工具调用等都属于 Harness。

**Salesforce 工业级拆解（7大核心功能）**：
- **状态持久化 & 错误恢复**：AI 系统具备自我修复能力，Harness 捕获错误并反馈给模型，让其反思和重试，而不是直接崩溃。
- **评估与度量**：将模糊的 AI 性能转化为可量化指标（任务成功率、工具调用准确率、错误恢复率等），实现持续优化。

### 核心思维转变：从“崩溃重启”到“自我修复”
在 AI 系统中，错误是常态，Harness 的职责是赋予系统**自我修复能力**。像带实习生一样，第一步做错了，指导他纠正，而不是直接开除。

## 三、产品设计提效工作流 (Stitch + Codex)

三步实现从高保真页面到 PRD 对齐：

1. **Stitch 快速生成高保真页面**

   - 使用 AI 功能生成页面初稿。
   - 用“高保真交互关联”功能验证交互逻辑。

2. **Codex 基于页面生成 PRD**
   - 在 Stitch 中导出 MCP 连接密钥。
   - 在 Codex 中配置 MCP，调用自定义 PRD skill 生成文档。
   - 审阅并修正 AI 生成的 PRD。

3. **Codex 反向修改 Stitch 页面**
   - 让 Codex 调用 MCP 直接修改 Stitch 画布中的页面。
   - 确保 PRD 和页面保持一致后重新关联交互，完成初稿。

## 七、从零搭建 AI 知识库（第一阶段总结）

核心成果：实现**知识检索层**，采用“向量检索 + LLM 重排”两阶段设计。

### 全流程
1. **统一入口**：多种格式文档（PDF、TXT 等）统一接口处理。
2. **文档分块**：将大文档分割成小片段，适配模型上下文限制。
3. **向量检索**：快速筛选所有可能相关的候选知识（Top 20），确保高召回。
4. **LLM 重排**：对候选知识精细排序，选出最适合回答当前问题的片段。

### 两阶段分离的优势
| 阶段 | 特点 | 作用 |
|-----|------|------|
| 向量检索 | 速度快，成本低 | “广撒网”，快速筛选少量候选 |
| LLM 重排 | 精度高，成本高 | “精挑细选”，深度判断选出最优 |

第一阶段实现了“把知识放进去，且能准确找回来”。下一步进入**知识生成**阶段，利用精准知识通过 LLM 生成自然语言回答，完成 RAG 闭环。

## 九、新兴模型范式 —— Cola DLM vs. ELF

两者共同目标：打破传统“逐词预测”，在连续语义空间中构思语言，一次性解码成文字。

| 对比维度 | Cola DLM | ELF |
|---------|---------|-----|
| 核心理念 | 分层信息分解，语义与实现分离 | 极致连续流程，端到端连续生成 |
| 处理空间 | 潜在语义空间扩散 | 原始词嵌入空间流匹配 |
| 核心架构 | Text VAE + 块因果 DiT | 共享权重网络统一去噪和解码 |
| 参数规模 | 约 2B | 约 105M |
| 训练成本 | 较高（约 2000 EFLOPs） | 极低（仅 45B training tokens） |
| 性能侧重 | 推理与语义任务优于自回归基线 | 极小参数达到低生成困惑度 24 |
| 开源程度 | 完全开源（论文、代码、权重、中文博客） | 开源论文与代码 |
