📋 各修复方案详解与操作

方案一：从备份恢复（首选，依赖事前准备）
此方案适用于拥有WAL日志与物理备份的场景，能实现最精准的恢复。

· 关键前提：数据库必须已开启 WAL归档 (archive_mode = on) 并存在基础物理备份。
· 如何操作：
  1. 确定出错前的正确时间点。
  2. 使用 pg_basebackup 或文件系统备份，结合WAL日志，执行 PITR。
  3. 在恢复配置（recovery.conf 或 postgresql.conf）中设置 recovery_target_time = '出错前的时间点'。
· 优点：可做到零数据丢失，恢复最完整。
· 缺点：需要提前严格配置备份系统。

方案二：从逻辑备份恢复（最常用）
此方案适用于定期使用 pg_dump 等工具进行逻辑备份的场景。

· 如何操作：使用 psql 或 pg_restore 将备份文件导入到新库或覆盖原库。
