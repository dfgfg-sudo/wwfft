第三部分：工作流调试实战（完整原文+修复）

原文标题：「极简」扣子(coze)教程 | 老司机秘籍，扣子调试实践II ,错误信息读取及定位
原文链接：https://blog.csdn.net/u014527622/article/details/148040278
遵循原则：以下逐字保留原文内容，并修复了技术描述中的不准确之处（如null的定义）。

3.1 原文开头

上一篇大师兄介绍了一下扣子调试技巧。这一篇我们将继续这个主题，并深入探讨一下通过错误信息定位错误节点的调试技巧。

3.2 错误信息

我们这里说的错误信息是指在运行时，节点获取了不符合输入要求的信息，或者运行时出错。这个时候节点就需要输出错误的信息帮助使用者通过调试技巧找到错误源，继而调试修改程序或者添加执行错误的处理程序。这个时候找到错误信息，看懂错误信息找到出错源头就非常重要了。

3.3 错误输入的例子

我们用上篇的工作流做例子。上篇我们在工作流的输入参数input中输入了一个链接。工作流可以正常的运行输出。这一次我们在同样的input参数中直接输入内容而不是链接，在点击运行后可以看到“大模型”节点显示了“运行失败”的告警标识（红色字）。而最后一个节点也没有运行，整个工作流就直接退出了。

3.4 查看错误信息

现在我们点击“大模型”的运行状态右边的这个详情按钮。可以看到错误输出信息。意思是“大模型”节点收到了不正确的“null”的数据。

原文注释：null是编程语言中经常使用的一个标志，其意思就是“没有”。我们的大模型收到了一个“空”的信息，自然没法运行。

3.5 找到真正的原因

所以运行出错的问题并不发生在“大模型”节点中，而是前面的“网页获取”节点的“空”输出。

原文提示：我们在调试的时候不能出错信息显示在哪里就判断为这个模块有问题，往往问题出现在他的周围。所以要自己阅读分析出错信息，才能判断真正出错的点。

我们点开前一个“网页内容”节点的详细信息。可以看到这个节点在运行中的接收到的参数，以及输出的参数。仔细看输出部分，他的data参数（我们在大模型节点中使用的输入值）是null。对比一下我们之前输入链接正常运行时的输出。可以发现这个值的输出null导致了问题。也就是说这次“网页获取”节点收到了一个不是网址的输入（我们直接输入了内容而不是网址），这个节点把这个内容当做了一个网址，去尝试读取内容，自然读不到任何的内容，于是就发出了“空”的信息给大模型。

3.6 调试技巧总结（原文）

调试的技巧：找到一个场景，在相同的情况下（输入，运行状态），总可以得到稳定可重现的结果。运行，获取运行中的记录（调试信息）。与正常情况中获取的信息进行对比，找到出问题的真实原因。

3.7 原文结尾

今天大师兄带大家解读了一个错误的案例。可以看到错误的信息对程序的调试至关重要，学会查看调试信息可以帮助我们定位问题，解决问题。
