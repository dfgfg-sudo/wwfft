## 一、项目概述

### 1.1 项目背景

用户拥有三个源文件（`coze.txt`、`rgtygfdjshg.txt`、`yryetrytudkz.txt`），其中包含 12 个独立插件和大量工具函数。这些源文件存在以下问题：

- **内容重复**：三个文件中存在大量重复的配置、路由关键词、模块定义和参数验证逻辑。
- **格式混乱**：Python 与 JavaScript 混合编写，handler 签名不统一，部分文件缺少 export 语句。
- **代码错误**：模板字符串转义错误、TypeScript 类型缺失、模块定义不一致。
- **中文文字问题**：部分注释和描述需要统一润色，错误提示信息格式不统一。

用户希望将这三个文件中的全部功能合并融合为 1 个超级插件和 1 个超级工具，同时修复全部中文文字和代码错误，确保可运行使用。

### 1.2 项目目标

构建一个 Coze 超级插件（CozeSuperUltimatePlugin），实现以下目标：

1. **全功能整合**：将三个源文件的全部 12 个插件、450+ 工具合并为 1 个统一插件，功能不删减、不遗漏。
2. **全节点封装**：对 Coze 画布全部 47 个节点进行统一封装，采用标准化的 handler 签名。
3. **自动诊断与修复**：集成自动修复引擎，自动诊断并修复工作流配置错误、橘黄色叹号、参数缺失、连接错误等常见问题。
4. **智能路由**：用户输入自然语言指令，插件自动识别意图并路由到对应模块执行。
5. **安全合规**：本地运行、零 Token 成本、完全免费，不收集敏感数据，不依赖外部服务。

### 1.3 项目范围

| 维度 | 范围说明 |
|------|----------|
| 源文件数量 | 3 个（coze.txt、rgtygfdjshg.txt、yryetrytudkz.txt） |
| 原始插件数量 | 12 个 |
| 合并后插件数量 | 1 个（CozeSuperUltimatePlugin） |
| 模块数量 | 30 个 |
| 工具数量 | 450+ |
| 节点封装数量 | 47 个 |
| 修复策略数量 | 9 种（基础）+ 5 种（高级） |
| 错误码覆盖 | 15 个 |
| 运行时 | Node.js（Coze IDE 标准） |
| 入口函数 | `export async function handler({ input, logger })` |

### 1.4 术语定义

| 术语 | 定义 |
|------|------|
| 模块（Module） | 插件中按功能划分的独立单元，每个模块包含若干工具 |
| 工具（Tool） | 模块内的具体功能函数，执行特定任务 |
| 节点（Node） | Coze 画布上的可视化组件，如大模型、代码、选择器等 |
| 路由（Routing） | 根据用户输入自动选择对应模块执行的机制 |
| 修复策略（Fix Strategy） | 针对特定错误类型的自动修复方案 |
| 橘黄色叹号 | Coze 画布上节点参数配置不完整时显示的警告标志 |
| 兜底处理 | 所有修复策略均失败时的最后处理方案 |

## 三、安全要求

### 3.1 安全总则

Coze 超级插件严格遵循安全合规原则，确保用户数据安全和隐私保护。所有功能在本地环境运行，不向外部服务器发送任何数据。

### 3.2 安全特性要求

| 需求编号 | 安全特性 | 要求描述 | 优先级 |
|----------|----------|----------|--------|
| REQ-3.1 | 本地运行 | 插件在本地环境运行，所有处理逻辑在本地完成，不向外部服务器发送数据 | 高 |
| REQ-3.2 | 零 Token 成本 | 插件运行不消耗任何 API Token，用户无需支付 Token 费用 | 高 |
| REQ-3.3 | 完全免费 | 插件完全免费使用，无任何付费门槛或功能限制 | 高 |
| REQ-3.4 | 无敏感数据 | 插件不收集、不存储、不传输任何敏感用户数据 | 高 |
| REQ-3.5 | 无外部服务依赖 | 插件不依赖任何外部第三方服务，完全自包含运行 | 高 |
| REQ-3.6 | 无端口暴露 | 插件不开放任何网络端口，不存在端口暴露风险 | 高 |
| REQ-3.7 | 输入安全处理 | 所有字符串输入经过 HTML 实体转义（<、>、"、'、\），防止 XSS 和注入攻击 | 高 |
| REQ-3.8 | 权限最小化 | 插件仅申请必要的读写权限（workflow、knowledge、bot、plugin、agent），不申请超出功能范围的权限 | 高 |

### 3.3 权限范围

插件申请的权限均为功能性必需权限，不包含任何超出功能范围的权限：

- `coze:workflow:read` / `coze:workflow:write`：工作流读取与写入
- `coze:knowledge:read` / `coze:knowledge:write`：知识库读取与写入
- `coze:bot:read` / `coze:bot:write`：Bot 读取与写入
- `coze:plugin:read` / `coze:plugin:write`：插件读取与写入
- `coze:agent:read` / `coze:agent:write`：智能体读取与写入

### 3.4 验收标准

- 插件运行过程中不产生任何网络请求（除 Coze 平台 API 调用外）。
- 不收集、不存储任何用户敏感信息（密码、密钥、个人信息等）。
- 所有字符串输入均经过安全转义处理。
- 权限申请范围不超过上述 10 项。

## 四、实现方式

### 4.1 技术选型

| 维度 | 选型 | 说明 |
|------|------|------|
| 运行时 | Node.js | Coze IDE 标准运行时，Python 代码转换为 JavaScript |
| 语言 | TypeScript / JavaScript | 核心模块使用 TypeScript，节点 handler 使用 JavaScript |
| 模块系统 | ES6 Module | 统一使用 export/import 语法，弃用 module.exports |
| 入口函数 | `export async function handler({ input, logger })` | Coze IDE 标准 handler 签名 |
| 版本 | 20.0.0 | 当前版本号 |

### 4.2 架构设计

```
coze-super-plugin/
├── manifest.json              # 插件清单（模块、节点、参数定义）
├── src/
│   ├── index.ts               # 统一入口（配置、路由、handler）
│   ├── core/
│   │   ├── PluginCore.ts      # 插件核心（节点注册、模块路由与执行）
│   │   └── AutoFixEngine.ts   # 自动修复引擎（9种基础策略 + 5种高级策略）
│   ├── modules/               # 30个模块执行器
│   └── handlers/              # 47个节点handler
├── merged/
│   └── CozeSuperUltimatePlugin.js  # 单文件合并版（可直接粘贴到Coze IDE）
└── docs/
    ├── tool-config.md         # 工具参数配置文档
    └── requirements-clean.md  # 需求文档（本文档）
```

### 4.3 实现步骤

| 步骤 | 操作 | 文件 | 说明 |
|------|------|------|------|
| 1 | 重写主入口 | `src/index.ts` | 合并三个文件的 CONFIG、ROUTING_KEYWORDS、MODULES_DEFINITION、ERROR_CODES，统一路由和 handler |
| 2 | 重写路由核心 | `src/core/PluginCore.ts` | 整合路由逻辑，保留节点注册管理，添加 30 个模块执行器映射 |
| 3 | 重写修复引擎 | `src/core/AutoFixEngine.ts` | Python 函数转 JavaScript，整合 CozePluginRepairEngine，保留修复策略 |
| 4 | 创建模块执行器 | `src/modules/*.js` | 为每个模块创建独立文件，合并各源文件的 executeModule 子函数 |
| 5 | 修复节点 handler | `src/handlers/*.js` | 统一为 `export async function handler({ input, logger })` 签名 |
| 6 | 更新清单 | `manifest.json` | 添加 30 个模块定义，更新版本号，完善元数据 |
| 7 | 生成单文件版 | `merged/CozeSuperUltimatePlugin.js` | 合并所有代码为单个文件，可直接粘贴到 Coze IDE |
| 8 | 生成参数文档 | `docs/tool-config.md` | 列出全部工具的输入/输出参数表格 |
| 9 | 生成需求文档 | `docs/requirements-clean.md` | 整理用户需求为结构化文档 |

### 4.4 关键决策

1. **统一运行时为 Node.js**：Coze IDE 标准运行时，Python 代码转换为 JavaScript。
2. **保留全部功能不删减**：三个文件的所有功能都保留，去重但不删功能。
3. **智能路由优先**：用户输入自然语言，自动路由到对应模块。
4. **双输出模式**：模块化项目结构 + 单文件合并版。
5. **参数规范统一**：所有工具使用统一的输入/输出 Schema。
6. **节点 handler 统一**：从 class 模式改为函数式 handler，符合 Coze IDE 规范。

### 5.3 修复模块详细划分

#### 5.3.1 橘黄色叹号修复（orange_exclamation_fix）

- **功能**：修复 Coze 画布上的橘黄色叹号警告
- **工具**：fixOrangeExclamation
- **触发条件**：节点参数配置不完整或类型不匹配
- **修复方式**：自动填充缺失参数，修复类型不匹配

#### 5.3.2 缺失参数修复（missing_param_fix）

- **功能**：自动填充缺失的必要参数
- **工具**：fixMissingParam
- **触发条件**：错误消息包含"缺少必要参数"
- **修复方式**：提取参数名，填充默认值

#### 5.3.3 连接错误修复（connection_error_fix）

- **功能**：修复节点连接错误
- **工具**：fixConnectionError
- **触发条件**：错误消息包含"connection"、"连接"
- **修复方式**：延迟 1 秒后重试

#### 5.3.4 超时重试（timeout_retry）

- **功能**：超时后自动重试
- **工具**：retryWithTimeout
- **触发条件**：错误消息包含"timeout"、"超时"或错误码 777777776
- **修复方式**：指数退避重试 3 次，间隔 2/4/8 秒

#### 5.3.5 Schema 验证（schema_validation）

- **功能**：验证和修复 Schema 配置
- **工具**：validateSchema
- **触发条件**：用户提供 schema 和 data
- **修复方式**：验证必填字段，返回验证错误

#### 5.3.6 卡片变量修复（card_variable_fix）

- **功能**：修复卡片变量缺失问题
- **工具**：cardVariableFiller
- **触发条件**：卡片模板含未提供的变量
- **修复方式**：自动填充缺失变量，生成渲染预览

#### 5.3.7 知识库重分段（knowledge_rechunk）

- **功能**：重新分段知识库内容
- **工具**：knowledgeRechunk
- **输入**：content、chunk_size、overlap
- **输出**：分段总数、分段内容数组

#### 5.3.8 兜底处理器（fallback_handler）

- **功能**：最后的兜底处理方案
- **工具**：fallbackHandle
- **触发条件**：所有其他修复策略均未成功
- **修复方式**：返回默认值 null，提示检查配置
