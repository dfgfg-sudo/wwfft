### 6.2 依赖缓存策略

### 6.3 安全扫描
- 使用 `gosec` 扫描 Go 代码漏洞。
- 使用 `actions/dependency-review-action` 检查 PR 中的依赖风险。

### 6.4 增量构建

## 2. 安全基础设施（不可突破的底线）

### 2.1 物理与网络隔离
- 每个AI员工运行在 **一次性微虚拟机（Firecracker）** 或 **Docker容器（带GUI支持）** 中，任务结束即销毁。
- 网络流量 **强制通过安全网关**，禁止任何直连外网；所有出口流量经网关认证、审计、限流。

### 2.2 安全网关与密钥管理
- **网关组件**：Kong / Apache APISIX + OPA（开放策略代理）
- **认证与授权**：mTLS双向认证 + OAuth2客户端凭证，确保调用方身份合法
- **动态密钥**：HashiCorp Vault 为每个任务临时生成API密钥、支付令牌，任务完成后自动撤销
- **请求签名**：关键交易（转账）使用硬件安全模块（HSM）签名，防篡改、抗抵赖

### 2.3 系统调用与资源限制
- 使用 **seccomp**、**AppArmor** 或 **SELinux** 限制容器内系统调用，禁止高危操作（如 `rm -rf`、`shutdown`、`format`）
- 资源配额：每个任务CPU ≤2核，内存 ≤4GB，执行时长 ≤30分钟（可配置）

### 2.4 全链路审计与熔断
- **实时录制**：屏幕录像（FFmpeg）+ 鼠标轨迹 + 键盘输入（脱敏）+ API请求/响应
- **存储**：不可变对象存储，保留至少180天
- **监控指标**：资源使用率、操作失败率、异常频率、执行时长、收益达成率
- **自动熔断**：
  - 失败率 > 30% → 暂停任务并尝试降级
  - 执行时间超过预期2倍 → 强制终止并回滚快照
  - 检测到异常行为（如访问非授权系统）→ 立即终止并告警

### 2.5 法律与合规前置
- 所有代码与数据存储于 **境内合规服务器**，满足《网络安全法》《数据安全法》《个人信息保护法》
- 资金流转通过 **持牌第三方支付机构**，绝不触碰非法集资、洗钱等红线
- 自动化操作严格遵守目标平台 **用户协议**，不使用外挂、恶意爬虫等违法手段
